§Executive summary

Sojourn is a genuinely impressive, well-crafted travel-journal platform. The design language is distinctive (a confident editorial dark theme), the feature set is deep (immersive maps, story scrubber, AI authoring with cost metering, collaborators with per-trip RLS, full-text + semantic search, PWA, web push, editable branding), and the engineering is unusually disciplined about graceful degradation. A prior bug-focused QA pass already hardened many sharp edges. This audit is broader — product, UX, clarity and code health — and it surfaces a smaller number of real defects plus a longer list of polish, resilience and reach opportunities.

Three things to fix first.
  • The home hero collapses to a black void whenever the newest post has no cover image — which is the current live state of the seed (the four newest "Tag N — stage" posts have cover_image = null). The most prominent surface of the site can render empty. (see A‑1)
  • A React hydration mismatch on /photos — the photo-strip re-applies a blurhash placeholder client-side only. It's the same class of bug that was already fixed in gallery.tsx, but the fix was never applied to photo-explorer.tsx. (see A‑2)
  • Reader writes silently lie. Failed comment posts keep the optimistic comment with no error, and in demo mode comments/reactions/votes look saved but aren't — with no signal at the point of interaction. (see B‑1, B‑2)

Beyond those, the dominant themes are: (1) coverless content looks broken across the whole app — empty dark cards read like loading skeletons; (2) reach is under-built — no sitemap, robots, RSS, structured data or canonical/hreflang for a public, SEO-relevant journal; (3) resilience gaps in the admin — no unsaved-changes guard or autosave in the editors, and several "feature not configured" paths dead-end instead of explaining themselves; and (4) observability is zero — there is not a single error log in src/, so the many deliberate best-effort catch {} blocks hide real outages in production.

§Method & scope

Two tracks ran in parallel:

  • Live exploration. The dev server ran against the local Supabase stack (.env.local) with the production-scale seed, so every feature was exercised with real data — including the admin, signed in as both owner@sojourn.test and (via the pre-existing session) a scoped collaborator. Screens were captured at 1440×900 and 390×844, in both German and English. Console, network and server logs were inspected per screen.
  • Code audit. Four independent passes over the codebase: (1) feature completeness & UX-from-code, (2) i18n integrity & copy quality, (3) code quality & architecture, (4) accessibility / SEO / performance.

Items already fixed by the prior QA pass (soft-404 noindex, the missing table GRANTs in migration 0020, the gallery.tsx hydration fix, comment-like a11y labels) are treated as done and not re-reported — except A‑2, where the same fix was needed in a second component and missed.

Note on one transient error. The home page first rendered a dev overlay (Element type is invalid… resolves to undefined at page.tsx:50). This was a stale .next cache artifact — it vanished after clearing the cache and rebuilding, and the imports/exports are correct. It is not a real bug and is recorded only so it isn't mistaken for one.

§What's working well

Worth stating plainly, because it frames everything below: this is a high-quality codebase and product. The findings are refinements on a strong base.

Strength

Distinctive, coherent design system

The editorial dark theme (Fraunces display + warm ember accents, grain texture, Ken-Burns hero, reveal-on-scroll) is opinionated and consistent across public and admin. The post-detail reading experience — full-bleed hero, sticky story-map, inline galleries, inline polls/quizzes — is genuinely magazine-grade.
Strength

Disciplined graceful degradation

The runtime-capability model (isSupabaseConfigured / isServiceRoleConfigured / isPushConfigured) with a demo-content fallback is elegant and lets the app run zero-config. Search transparently degrades from semantic to full-text. Migrations enable RLS on every table; SECURITY DEFINER functions pin search_path; invite tokens are sha256-hashed; quiz answers are never sent pre-vote.
Strength

Deep, well-built admin

The post editor (SETUP panels for trip/photos/GPS/interactions, an insert palette for inline refs, an AI-assist panel with per-language target, a sticky Save/Publish bar) is thoughtfully structured. Collaborators with per-trip grants and correct RLS scoping, a threaded moderation surface, editable per-language branding with a live preview, and an AI cost/token dashboard are all polished and functional.
Strength

i18n integrity is excellent

EN/DE key parity is perfect (439 keys each) and compile-time enforced via type Dict = Record<keyof typeof en, string>. German register is consistently informal ("du"), and empty/error states in the dictionary are unusually well-written and actionable — no generic "Something went wrong".

ACorrectness & bugs

A‑1High

Home hero collapses to an empty black band when the lead post has no cover image

The hero only renders an image when hero?.cover_image is truthy (src/app/page.tsx:36). The newest post becomes the hero (page.tsx:29). With the current seed the four newest published posts ("Tag 1–4 — stage") have cover_image = null, so above the fold the user sees a full-viewport black rectangle with only the kicker + headline text. Verified live: the hero <section> contains zero <img> elements. It's most jarring on mobile, where the void fills nearly the whole first screen.
Why it matters
An author can publish a coverless note at any time and silently break the site's most prominent surface. This is a resilience gap, not just a seed artifact.
RecommendationPick the newest post that has a cover for the hero (fall back through the list), and/or render a branded fallback (gradient + site mark, or a representative trip/photo cover) when none exists. At minimum, never let the hero be a bare black box.
A‑2High

Hydration mismatch on /photos — blurhash re-applied client-side only

Verified live in the console: "A tree hydrated but some attributes of the server rendered HTML didn't match… This won't be patched up", repeated for every filmstrip thumbnail. The diff is style.backgroundImage being added on the client. Root cause: src/components/photo-explorer.tsx:396 calls blurhashToDataURL(p.blurhash) during render and applies it at :418-420; the decoder returns null on the server (no <canvas>) but a data-URL on the client → server/client mismatch.
Why it matters
This is the identical bug class fixed in gallery.tsx during the prior QA pass (the "mount-gate the blur" fix), but photo-explorer.tsx was never given the same treatment. It now fires on every /photos load because the seed photos carry blurhashes. React abandons patching that subtree.
RecommendationApply the same SSR-safe pattern: gate blur behind a mounted flag (useState(false) + useEffect) so the first client render matches the server, then paint the placeholder on the next tick. Consider extracting the gallery's already-correct logic into a shared <BlurImg> so this can't drift again.
A‑3Medium

Live query failures silently fall back to fabricated demo content (inconsistently)

In src/lib/content.ts, some readers fall back to demo data on error (getPublishedPosts:~90, getTrips:~307, getGeotaggedPhotos:~429) while siblings fall back to empty (getPostSummaries:~191, getPublishedPostsByTrip:~212, getMapPosts:~143). So a transient Supabase failure on a configured site can show Patagonia/Japan demo posts on the homepage while the trip page shows nothing — confusing and potentially misleading.
RecommendationFall back to demo content only when Supabase is unconfigured; on a live query error return empty, consistently. Don't conflate "no backend" with "backend errored".
A‑4Medium

Background AI / translation jobs can hang in pending forever

src/lib/ai/jobs.ts:~51-85 and translate.ts:~20-38 set a row to pending then fire an Edge Function (or run a slow model call inline). If the function is killed at maxDuration, or accepts-then-crashes, the row is never resolved — and the poll route polls a pending row indefinitely. There is no timeout/reaper.
RecommendationAdd a stale-job sweep (mark pending rows older than N minutes as error) and/or a client-side poll timeout that surfaces a retry.
A‑5Low

"Recent comments" on the dashboard can show visually-identical rows

On the collaborator dashboard the recent-comments list rendered six identical "Jonas — Kommentar 1" rows. This is most likely a seed coincidence (scoped to one trip whose posts share a comment template), but it reads as a dedupe bug. Worth confirming the query orders by created_at and isn't repeating a join row.
A‑6Low

Unauthenticated DELETE /api/push removes any subscription by endpoint

src/app/api/push/route.ts:~60-71 deletes by endpoint string with no auth. Endpoints are high-entropy so practical risk is low, but anyone who learns one can unsubscribe that browser. Add a minimal ownership check or accept it explicitly with a comment.

BUX & clarity

B‑1High

Comment submission swallows failures — the reader thinks it posted

src/components/comments.tsx:~89-99: on a failed POST the catch keeps the optimistic comment and shows nothing — no error, no retry, no revert. On refresh the comment is gone. There is also no pending state on the submit button and no success confirmation.
RecommendationRevert the optimistic comment on error and show an inline error with retry; add a pending state to the submit button and a brief success acknowledgement.
B‑2High

Demo mode fakes persistence at the point of interaction

A demo notice lives in the footer, but the interactive controls don't say anything. In demo mode comments accept input and show an optimistic comment that never persists (comments.tsx:~40,86-99), reactions optimistically increment then fail silently (reactions.tsx), and poll/quiz votes show a tally that resets on refresh. Admin moderation buttons are also live-looking but inert.
RecommendationWhen !isSupabaseConfigured, disable these controls (or show an inline "saved only when a backend is connected" note) instead of relying on a footnote. Don't render false "it worked" affordances.
B‑3High

No unsaved-changes guard or autosave in the editors

Neither the post editor nor the trip editor has a beforeunload dirty-state warning or periodic autosave. A long composing session lost to a tab close, navigation, or crash is unrecoverable — a real data-loss risk for the person doing the most work in the app.
RecommendationAdd a dirty-state beforeunload prompt at minimum; ideally localStorage draft snapshots restored on reopen. (The app already creates an instant DB draft on "New post" — extend that to periodic saves.)
B‑4Medium

Search failure looks like "no results"

search-results.tsx collapses a failed /api/search into an empty result set, so a 500 reads as "No results for X." Add a distinct "Search is unavailable — retry" state.
B‑5Medium

Destructive actions are confirmed unevenly

Post and trip deletion use a confirm dialog; photo deletion (photo-manager.tsx:~143) deletes immediately with no confirm and no rollback on failure, and the writing-style "Propose from posts" overwrite has no guard. One destructive-action policy should cover all of them.
B‑6Medium

"Feature not configured" dead-ends instead of explaining itself

When AI keys are absent the draft/enrich buttons appear functional then error or no-op; inline polls/quizzes silently vanish without a service role (content.ts:~709-721 returns []); the translation badge promises "translated automatically when published" even when the translate Edge Function isn't configured. Gate these on the relevant capability flag and show an explicit "set X to enable" hint.
B‑7Medium

Push-"blocked" help appears as a full-screen dimming modal over the dashboard

On the owner dashboard the notification-permission help ("Re-enable in your browser: the lock icon → Site settings → Notifications → Allow") opened as a large overlay that dimmed the entire page on load. For a denied-permission hint this is heavier than warranted. Prefer the inline "Blocked in browser" chip (already present) with the help as a popover anchored to it, not a page-blocking modal.
B‑8Low

Disabled publish/required-field controls give no reason

The publish button disables on !title || !trip_id with no explanation; the trip-editor title is required with no inline cue. Add a tooltip/inline reason on the disabled control.
B‑9Low

Map/location picker has no error state

location-picker.tsx initializes MapLibre with no try/catch; a tile/network failure leaves a blank box. Add a fallback message.
B‑10Low

Editor routes lack loading skeletons that the public routes have

Public routes ship rich, layout-matched loading.tsx files; the admin editor routes don't, so they flash blank during fetch while the rest of the app skeletons. Add form-shaped skeletons for parity.
B‑11Nit

Forms have no shared "unsaved" indicator

Branding / writing-style forms clear a "Saved" flag on edit but show no "unsaved" state and no nav guard. A single shared dirty-state pattern would unify B‑3 and these.

CVisual design & content presentation

C‑1High

Coverless posts render as empty dark rectangles everywhere

Post cards fall back to a near-black gradient placeholder when there's no cover. With the current seed (many coverless "stage" posts) the home grid, /posts, trip detail, and the admin posts list are dominated by empty boxes that read like unfinished loading skeletons. It undercuts the otherwise premium feel.
RecommendationGive coverless cards a real fallback: a deterministic gradient seeded by the title, a large initial/monogram, the trip's cover, or the location on a tiny static map. This single change dramatically lifts the perceived polish of every index.
C‑2Medium

Blur-up placeholder never shows in the marketed demo

Blurhash is fully implemented for live uploads (upload-client.ts encodes on upload), but every demo photo has blurhash: null (src/lib/demo.ts). So the headline blur-up nicety is invisible in the zero-config demo the README sells as "fully populated". Precompute static blurhash strings for the bundled demo photos.
C‑3Medium

Translucent text risks failing contrast on dark

Pervasive text-sand-100/40–/60 on ink-950/ink-900 (e.g. page.tsx:86,132; post-view.tsx:161; nav site-header.tsx:119). At 40–50% alpha, normal-size text likely drops below WCAG AA 4.5:1. Raise body/caption text to ≥70% alpha and reserve very-low alpha for large display text. (Also a11y — see F‑4.)
C‑4Low

Empty-trip subtitle/label mixes languages under EN

"Leere Expedition / Noch keine Einträge" shows German while the UI is English. If "no entries yet" is a system label it should be localized; if it's trip-authored copy it's the expected source-language fallback (see E‑5). Worth confirming which.
C‑5Nit

Dark-only by design isn't stated

No light theme or prefers-color-scheme handling. Almost certainly intentional (the aesthetic depends on it) — just document "dark by design" so it isn't read as missing.

DFeatures & gaps

D‑1High

README roadmap is stale — it undersells shipped work

README.md:197-198 lists blurhash generation and the maskable PWA icon as roadmap, but both are shipped: upload-client.ts encodes a blurhash on every upload, and public/icon-maskable.svg is registered with "purpose":"maskable" in the manifest. A stale roadmap makes the project look less complete than it is and risks someone re-building done work.
RecommendationMove blurhash + maskable icon into Features. The genuine remaining gaps are RSS, OG/share images, and sitemap/robots (below).
D‑2Medium

No RSS / Atom / JSON feed

No feed route exists; a travel journal with no feed loses subscribers. Add src/app/feed.xml/route.ts from published posts. (Also G — reach.)
D‑3Medium

No share affordance & no dynamic OG images

No copy-link / navigator.share() button on posts, and no generated per-post Open Graph image — so shared links preview poorly. Add a share button + next/og opengraph-image.tsx for posts/trips.
D‑4Medium

No tags / categories / topical browse

Post/PostSummary have no tags field; readers can only browse by trip or search. Optional tags with /posts/tags/[tag] would add a useful discovery axis.
D‑5Medium

No "related / more from this trip" — standalone posts dead-end

Only trip prev/next exists; a post not in a trip dead-ends after comments. Embeddings already exist (chunk-index), so a semantic "related posts" block is cheap and would deepen sessions.
D‑6Low

Map clustering absent

Roadmap item; fine at current scale but /map and /photos will crowd as pins accumulate.
D‑7Low

Pagination only on /posts

/trips and /photos render everything. Reasonable now; note the asymmetry deliberately (ties into H‑2).
D‑8Nit

No light theme toggle

See C‑5 — likely intentional.
D‑9Nit

No reading-progress / table-of-contents on long posts

Long story posts could benefit from a progress bar or section nav, given the immersive format.

EInternationalization & copy

Baseline is strong: perfect EN/DE key parity (439 each), compile-time enforced, consistent informal German, and high-quality error/empty states. Findings below are the edges.
E‑1High

Photos page title is hardcoded English (violates the "no hard-coded strings" rule)

src/app/photos/page.tsx:5 — export const metadata = { title: "Photo map" }. It's the only page that bypasses defaultTitle("meta.…"); German users get an English tab/SEO title. A photos.title key already exists ("Photo map" / "Fotokarte").
Recommendationtitle: defaultTitle("photos.title") (or add a meta.photos key for consistency with the other meta.* titles).
E‑2Medium

Client-side error strings bypass i18n and leak raw backend messages

User-visible error state is set with hardcoded English fallbacks and, worse, raw Supabase error.message: photo-manager.tsx:93,137, track-manager.tsx:54,83, image-uploader.tsx:35, branding-form.tsx:74,79, writing-style-form.tsx:39,44,63,69, ai-context-refiner.tsx:50,60. These render in the red error <p> in both languages.
RecommendationMap known failures to localized keys (e.g. admin.gallery.uploadFailed); show a generic localized message for unknown errors instead of the raw English string.
E‑3Medium

Two button keys are byte-identical — a label distinction was lost

i18n.ts:429-430: admin.ai.generate and admin.ai.skip are both "Generate draft" (de both "Entwurf erstellen"). A key named skip rendering "Generate draft" is confusing and suggests the skip path lost its real label. Give it a distinct label (e.g. "Skip questions & generate") or remove if dead.
E‑4Medium

admin.account.errGeneric asserts a demo-mode cause for any failure

i18n.ts:275/805: the "generic error" key reads "Not available in demo mode." If it's the fallback for any password-change failure, a real production failure will wrongly blame demo mode. Split into a true generic message + a separate demo-mode message, or confirm it's only used in demo.
E‑5Low

Content fields (location, captions, untranslated trip/post copy) stay source-language under EN

Observed live: "El Chaltén, Argentinien" and German photo captions while reading in English; trips without an EN translation show German subtitles. This is the documented "body in source language" design, not a bug — but it produces visibly mixed-language pages. Decide whether locations/short captions should be translatable (they're high-visibility, low-effort) and whether to label untranslated content.
E‑6Low

comments.reply and comments.send both read "Reply"

i18n.ts:62,64. The reply submit button reading "Reply" next to the "Reply" toggle is ambiguous; make comments.send "Send" / "Senden".
E‑7Nit

German plural inconsistency: "Quiz" vs "Quizze"

i18n.ts:860 ("Umfragen & Quiz") vs :1043 ("Umfragen & Quizze") within the same feature. Pick one.
E‑8Nit

admin.ask.edit vs editing collide in German

i18n.ts:1048/1051 both render "Bearbeiten", losing the EN action/state distinction. Use "Wird bearbeitet" / "In Bearbeitung" for the state.
E‑9Nit

Trailing/leading spaces in several values

quiz.right, quiz.wrong, poll.thanks (i18n.ts:138-140) and admin.cmod.recent200 (:280) carry stray spaces implying concatenation. Verify they're concatenated; otherwise trim.

FAccessibility

Prior QA confirmed solid basics on public pages (single h1, alt text, labeled inputs/buttons). These are the gaps beyond that.

F‑1High

framer-motion animations ignore prefers-reduced-motion

The site-wide Reveal wrapper (src/components/reveal.tsx:15-25, used for every home section + card) animates opacity + 22px translate with no reduced-motion guard — while the CSS-based RevealChildren and globals.css:210-216 do honor it. The lightbox, gallery, comments and reactions animate unconditionally too.
RecommendationGate framer transitions on useReducedMotion() (zero-duration / initial=false when requested); centralize in Reveal.
F‑2High

Modals/lightbox don't trap or restore focus

image-lightbox.tsx:97-175 sets role="dialog" aria-modal and handles Escape but never moves focus into the dialog, traps Tab, or restores focus to the trigger on close. confirm-dialog.tsx and location-dialog.tsx have the same gap (and miss aria-labelledby/describedby). Keyboard/SR users are left behind the overlay.
RecommendationOn open, focus the dialog (or first focusable), trap Tab, restore focus on close; wire aria-labelledby/aria-describedby.
F‑3Medium

SSR <html lang> and metadata are always German

layout.tsx:61 hardcodes lang="de"; the client corrects it post-hydration (i18n.tsx:72), but server HTML (crawlers, no-JS AT) always claims German even for English content, and metadata is rendered in the default locale. Resolve locale server-side from the cookie and set lang + metadata accordingly. (Ties into G‑3.)
F‑4Medium

Low-contrast translucent text

Same root as C‑3: text-sand-100/40–60 on dark likely fails AA for normal text. Audit each token against its background; keep small text ≥4.5:1.
F‑5Low

Smooth-scroll not disabled under reduced-motion

globals.css:38-40 sets scroll-behavior:smooth globally; add scroll-behavior:auto inside the reduced-motion block.
F‑6Low

Filmstrip thumbnails use empty alt

photo-explorer.tsx:415 uses alt={p.caption ?? ""}; content thumbnails with no caption become decorative to a screen reader. Fall back to the post title (the button already uses it as title).

GSEO & reach

G‑1High

No sitemap.xml and no robots.txt

Neither src/app/sitemap.ts nor robots.ts exists. For a public journal with ~50 posts + 8 trips, crawlers get no index. metadataBase is already set, so both are trivial in the App Router (enumerate posts/trips for the sitemap).
G‑2High

No structured data (JSON-LD)

No application/ld+json anywhere. Add Article/BlogPosting on posts (headline, datePublished, image, author, description) and WebSite + SearchAction on the home page for richer search results.
G‑3High

No canonical URLs / no hreflang for the bilingual site

No alternates.canonical or languages on any page. With DE/EN served from one URL via cookie, there are no hreflang signals and no canonical, risking duplicate-content ambiguity. Set alternates.canonical per page.
G‑4Medium

OG/Twitter cards are thin

posts/[slug]/page.tsx:34-38 sets openGraph.images to the raw cover URL (no width/height/alt); there's no twitter card block anywhere and no default OG image in the root layout. Add twitter:{card:"summary_large_image"}, OG image dimensions + alt, and consider generated cards (D‑3).
G‑5Medium

RSS/Atom feed missing

Same as D‑2 — counts for reach as much as features.
G‑6Medium

Hardcoded English metadata title on Photos

Same as E‑1 — a German user's photos tab is mislabeled to crawlers and browsers.
G‑7Low

Listing pages have no description

/posts, /trips, /map, /search, /photos set only a title; add per-page descriptions.
G‑8Low

Metadata rendered in a fixed locale

Crawlers see a fixed-language snapshot (ties into F‑3/G‑3). Resolve from the cookie server-side.

HPerformance

H‑1High

maplibre-gl is imported eagerly into route bundles

All five map components top-level import maplibregl from "maplibre-gl" with no next/dynamic. TripMap is rendered statically by post-view.tsx:253, so maplibre (~200KB+ gzipped) ships in the client bundle of every post page — even posts with no map.
RecommendationLoad map components via next/dynamic(() => import(...), { ssr:false, loading:… }), gated on hasMap, so maplibre is fetched only when a map actually renders.
H‑2Medium

/posts fetches up to 1000 full posts with no virtualization

posts/page.tsx:14 pulls up to 1000 posts and ships them to a client-paginated grid. Payload and client memory grow linearly with content; the grid isn't windowed. Paginate server-side and/or virtualize. (Related: getPublishedPosts selects full bodies + all relations + every reaction row unbounded — see I‑3.)
H‑3Low

First above-the-fold card cover isn't prioritized

PostCard defaults priority=false; on /posts and trip detail the first card LCP is lazy-loaded. Pass priority to the first 1–2 cards per grid.
H‑4Low

Lightbox loads two full-size tiers (1600 + 2560px)

image-lightbox.tsx:147-169 always requests both. Skip the 2560 tier on small/low-DPR screens.
H‑5Nit

Fraunces loads 3 variable axes

layout.tsx:23-28 loads opsz/SOFT/WONK; drop unused axes to shrink the font payload. (display:swap already set — good.)

ICode quality & architecture

Overall well-organized and disciplined. Findings are mostly Medium/Low — debt that will bite at scale or hide failures.

I‑1High

Public writes run on the service-role client & have no rate limiting

comments/route.ts:52, comments/like/route.ts:21, reactions/route.ts:48 do (await getServerSupabase()) ?? getAdminSupabase(); for an anonymous visitor there's no session, so the service-role client is used, bypassing RLS entirely. interactions uses the admin client unconditionally. So zod validation is the only gate on the common path, there's no abuse protection anywhere, and comment bodies (≤4000 chars) are stored raw — XSS safety rests entirely on the render layer escaping them.
Recommendation(a) confirm the render path escapes comment bodies (React escapes by default — verify no dangerouslySetInnerHTML on user text); (b) add per-IP / per-token rate limiting on comment/reaction/interaction POSTs; (c) prefer the anon client so RLS is the real gate, falling back to service-role only when necessary.
I‑2Medium

Zero observability — no error logging anywhere in src/

There is not a single console.error in the tree. The data layer and AI/geocode/translate/usage helpers all swallow errors to null/empty by design. A real outage (Supabase down, embeddings 500ing, geocode quota exhausted) is completely invisible in production.
RecommendationRoute swallowed errors through a single logError(scope, err) seam (no-op in tests) so failures are observable without changing the graceful fallback.
I‑3Medium

Unbounded over-fetch on hot read paths

getPublishedPosts/getPublishedPostsByTrip select full bodies + all photos/locations/tracks + every reaction row (counted client-side in summarizeReactions) for every post, with no limit. getPostSummaries exists to avoid this — confirm hot paths use it, and replace the per-row reaction fetch with an aggregate count.
I‑4Medium

Per-option N+1 COUNT on the unauthenticated interactions endpoint

interactions/route.ts:36-45 issues one count query per poll option on every load/vote, on the service-role client — an unauthenticated DB-load multiplier. Replace with a single group-by (or an RPC returning tallies).
I‑5Medium

Duplicated auth preamble & post upsert logic across routes

requireOwner() is copy-pasted in three members routes; requireUser() in two more; the get-session→401 block is hand-written in ~10 routes. POST and PUT for posts share an identical zod schema + materialize/translate/notify sequence with subtle drift (PUT never re-checks trip_id against the collaborator's grants — it relies on RLS). The adminRoute factory already proves the pattern; extend it to the non-AI admin routes and extract a shared upsertPost core.
I‑6Medium

Inconsistent error-response shapes; raw DB messages leak to clients

Bodies vary ({error:"invalid"}, {error:"forbidden"}, {error:error.message}) and the same 503 condition has four different strings ("unconfigured" / "not configured" / "Supabase not configured" / "unavailable"). Several routes return raw error.message to clients. Standardize via the factory; log details, return generic messages.
I‑7Medium

push_subscriptions.audience is unindexed

Every notification fan-out filters on audience (notify.ts:61-64,108-111) but there's no index (migration 0002) — a full scan per send. Add create index … on push_subscriptions(audience).
I‑8Low

any at the DB hydration boundary

content.ts uses any in ~7 spots (hydratePost(row:any) :47, casts at :145/151/431, hydratePhotoResult(row:any) :547). A renamed column compiles clean and fails at runtime. Type raw rows with a minimal interface or validate with a small zod schema at the boundary.
I‑9Low

Non-null assertion defeats the codebase's careful null-safety

admin/ai-usage/page.tsx:37 uses supabase!.rpc(...); early-return on null instead of asserting.
I‑10Low

Duplicated helpers worth consolidating

trimTitleI18n / postTitleI18n / trimCaptionI18n in content.ts do near-identical i18n trimming; summarizeReactions is re-implemented inline in reactions/route.ts:34-38. Consolidate.
I‑11Low

Search does two round-trips per query

RPC → re-fetch full rows by id → re-sort (searchPosts:505-522). Documented and reasonable; the RPC could return card columns directly to skip the second query.
I‑12Nit

Workspace-root warning from a stray lockfile

Dev server warns it inferred the workspace root from C:\Users\Philipp\package-lock.json (a second lockfile above the project). Set outputFileTracingRoot in next.config or remove the stray lockfile to silence it and avoid surprising file-tracing in standalone builds.

JSecurity & data integrity

The migration layer is clean: RLS on every table, SECURITY DEFINER functions pin search_path, service-role-only tables (ai_jobs, member_invites) have RLS-on + no policies, invite tokens are sha256-hashed, and quiz answers/explanations are never anon-readable. The prior pass also fixed the missing table GRANTs (migration 0020).
J‑1High

No abuse protection on anonymous writes

Same root as I‑1: comment/reaction/interaction POSTs are unauthenticated, run on the service-role client, and have no rate limiting or captcha. A bot can flood comments (the seed already shows 121 "Massenkommentar" on one post). Add per-IP/token throttling and consider a lightweight challenge.
J‑2Medium

Confirm comment bodies are escaped on render

Bodies are stored raw; XSS safety depends entirely on the render layer. React escapes text by default, but verify no comment/markdown path uses dangerouslySetInnerHTML on user content, and that the markdown renderer (react-markdown + remark-gfm) for post bodies doesn't allow raw HTML for collaborators.
J‑3Medium

Push scoping is enforced in app code, not RLS

Collaborator notification scoping lives only in notify.ts:112-114 (the table is service-role-only). Acceptable, but a logic bug there leaks notifications across collaborators — worth a test.
J‑4Low

Local .env.production points a local build at the live DB

Per the prior QA note, next build/start loads .env.production (live Supabase, anon key). Harmless for reads, but never run write-flow tests against a prod-built local server. Worth a one-line README warning.
